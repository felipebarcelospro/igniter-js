## Transports

Transports determine **where your log entries are written**. Logger ships with three built-in transports and supports any external pino-compatible transport. You can configure multiple transports — each log call writes to all of them simultaneously.

### Transport Architecture

Every transport is resolved at `.build()` time. The builder stores transport configurations; the manager passes them to Pino, which handles the actual output.

```
.addTransport({ target: 'console', options: {...} })
.addTransport({ target: 'file',    options: {...} })
.addTransport({ target: 'http',    options: {...} })
.addTransport({ target: '@logtail/pino', options: {...} })
                    │
                    ▼
              .build()
                    │
    ┌───────────────┼───────────────┐
    ▼               ▼               ▼
┌───────┐     ┌────────┐     ┌────────┐
│console│     │  file  │     │  http  │   ...
└───────┘     └────────┘     └────────┘
```

<Callout type="info">
  If **no transports** are configured, a console transport with pretty formatting is added automatically. You always get output somewhere.
</Callout>

## Console Transport

The console transport uses `pino-pretty` under the hood. It's the default when no transports are specified.

```typescript
import { IgniterLogger } from '@igniter-js/logger';

const logger = IgniterLogger.create()
  .addTransport({
    target: 'console',
    options: {
      colorize: true,
      translateTime: 'SYS:HH:MM:ss',
    },
  })
  .build();

logger.info('Pretty output with colors and timestamps');
```

### Console Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `pretty` | `boolean` | — | Present in the options type but does not disable the `pino-pretty` target selected by `console`. Use a raw Pino target or external transport when you need JSON lines. |
| `colorize` | `boolean` | `true` | Enable ANSI color output. Turn off in CI environments or when piping output. |
| `translateTime` | `string \| boolean` | `"SYS:standard"` | Time format. Use `"SYS:HH:MM:ss"` for 24h, `false` to disable timestamps. |
| `destination` | `"stdout" \| "stderr" \| string` | `"stdout"` | Output stream. Choosing `"stderr"` redirects the console stream; it does not filter log levels. |

### Examples

<Tabs items={['Pretty (default)', 'No color']}>
  <Tab value="Pretty (default)">
    ```typescript
    const logger = IgniterLogger.create()
      .addTransport({ target: 'console' })
      .build();

    // [12:34:56] INFO: Server started on port 3000
    ```
  </Tab>
  <Tab value="No color">
    ```typescript
    const logger = IgniterLogger.create()
      .addTransport({
        target: 'console',
        options: { colorize: false },
      })
      .build();

    // Plain text output — ideal for CI logs
    ```
  </Tab>
</Tabs>

<Callout type="info">
  `colorize: false` only removes ANSI colors; output remains `pino-pretty` text and does not become JSON. Use a raw Pino target or external transport for JSON lines.
</Callout>

## File Transport

The file transport writes logs to disk using Pino's built-in `pino/file` target. It creates parent directories by default. Although the exported `FileTransportOptions` type includes a `rotation` field, the resolver forwards that field to `pino/file`; this package does not implement rotation itself. Use an external Pino transport such as `pino-roll` when you need rotation.

```typescript
import { IgniterLogger } from '@igniter-js/logger';

const logger = IgniterLogger.create()
  .addTransport({
    target: 'file',
    options: {
      path: './logs/app.log',
      mkdir: true,
    },
  })
  .build();

logger.info('Written to file');
```

### File Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `path` | `string` | **required** | Destination file path. Absolute or relative to `cwd`. |
| `mkdir` | `boolean` | `true` | Create parent directories if they don't exist. |
<Callout type="warn">
  `rotation` is present in the public type for compatibility, but the built-in resolver does not translate it into a rotation-capable target. Configure rotation through a dedicated external transport instead.
</Callout>

### Example: Production File Logging

```typescript
import { IgniterLogger, IgniterLogLevel } from '@igniter-js/logger';

const logger = IgniterLogger.create()
  .withLevel(IgniterLogLevel.Info)
  .withAppName('api')
  .addTransport({
    target: 'file',
    options: {
      path: '/var/log/myapp/app.log',
      mkdir: true,
    },
  })
  .build();

// Flush before graceful shutdown
process.on('SIGTERM', async () => {
  logger.info('Shutting down');
  await logger.flush();
  process.exit(0);
});
```

## HTTP Transport

The HTTP transport sends logs to a remote endpoint asynchronously. It **buffers and batches** log entries to avoid blocking your application.

```typescript
import { IgniterLogger } from '@igniter-js/logger';

const logger = IgniterLogger.create()
  .addTransport({
    target: 'http',
    options: {
      url: 'https://logs.example.com/ingest',
      headers: {
        'X-API-Key': process.env.LOG_API_KEY!,
        'X-Service': 'api',
      },
      batchSize: 100,
      timeoutMs: 5000,
      flushInterval: 5000,
    },
  })
  .build();

logger.info('Sent to remote log aggregator');
```

### How It Works

1. Each log call pushes an entry into an **in-memory buffer** (async, non-blocking).
2. When the buffer reaches `batchSize`, or every `flushInterval` ms, entries are sent as a single HTTP POST.
3. If the request fails (network error or non-2xx), entries are put back in the in-memory buffer for another periodic or worker-close attempt. This is not durable storage; a process exit can lose buffered entries.
4. When Pino closes the transport, it requests a final flush. A failed final request is not persisted outside the process.

<Callout type="info">
  The HTTP transport uses a **custom Pino transport worker** (`http-pino-transport.ts`). Log calls enqueue entries for asynchronous delivery; network work can still delay transport shutdown while a flush is pending.
</Callout>

### HTTP Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `url` | `string` | **required** | Target URL for log ingestion. Must accept POST with JSON body. |
| `headers` | `Record<string, string>` | `{}` | HTTP headers for authentication or metadata (API keys, service name). |
| `batchSize` | `number` | `10` | Number of entries per batch. Flush triggers when this threshold is reached. |
| `timeoutMs` | `number` | `5000` | Request timeout in milliseconds. Uses `AbortSignal.timeout()`. |
| `flushInterval` | `number` | `5000` | Periodic flush interval in milliseconds. |

### Request Format

The HTTP transport sends a JSON POST with this structure:

```json
{
  "logs": [
    { "level": 30, "time": "2026-06-02T12:34:56.789Z", "msg": "Server started" },
    { "level": 50, "time": "2026-06-02T12:34:57.123Z", "msg": "Connection failed", "err": {...} }
  ],
  "timestamp": "2026-06-02T12:34:57.456Z"
}
```

## External Transports

Any **pino-compatible transport** can be used by passing its package name as the `target`:

```typescript
import { IgniterLogger } from '@igniter-js/logger';

// pino-pretty is already a direct dependency of @igniter-js/logger.
const prettyLogger = IgniterLogger.create()
  .addTransport({
    target: 'pino-pretty',
    options: {
      colorize: true,
      translateTime: 'SYS:standard',
      ignore: 'pid,hostname',
    },
  })
  .build();

// SaaS log aggregator (e.g., Logtail)
const remoteLogger = IgniterLogger.create()
  .addTransport({
    target: '@logtail/pino',
    options: {
      sourceToken: process.env.LOGTAIL_TOKEN!,
    },
  })
  .build();
```

### Popular External Transports

| Transport | Install | Use Case |
|-----------|---------|----------|
| `pino-pretty` | Included with `@igniter-js/logger` | Advanced pretty-printing with custom color schemes |
| `@logtail/pino` | `npm install @logtail/pino` | Logtail / Better Stack log management |
| `pino-datadog-transport` | `npm install pino-datadog-transport` | Datadog log ingestion |
| `pino-loki` | `npm install pino-loki` | Grafana Loki log aggregation |
| `pino-elasticsearch` | `npm install pino-elasticsearch` | Elasticsearch indexing |
| `pino-roll` | `npm install pino-roll` | Advanced file rotation with compression |
| `pino-sentry-transport` | `npm install pino-sentry-transport` | Sentry error tracking |

<Callout type="info">
  External transports receive the same log entries as built-in ones. Logger does not modify the payload — Pino passes entries directly to the transport.
</Callout>

## Multi-Transport Patterns

### Development vs Production

Use different transport configurations based on the environment:

```typescript
import { IgniterLogger, IgniterLogLevel } from '@igniter-js/logger';

const isDev = process.env.NODE_ENV !== 'production';

// Console uses pino-pretty in both environments; production output is uncolored.
let builder = IgniterLogger.create()
  .withLevel(isDev ? IgniterLogLevel.Debug : IgniterLogLevel.Info)
  .withAppName('api')
  .addTransport({
    target: 'console',
    options: { colorize: isDev },
  });

// File only in production
if (!isDev) {
  builder = builder.addTransport({
    target: 'file',
    options: { path: '/var/log/api/app.log', mkdir: true },
  });
}

// HTTP only in production
if (!isDev) {
  builder = builder.addTransport({
    target: 'http',
    options: {
      url: process.env.LOG_INGEST_URL!,
      headers: { 'X-API-Key': process.env.LOG_API_KEY! },
    },
  });
}

const log = builder.build();

log.info(`Logger started in ${isDev ? 'development' : 'production'} mode`);
```

### Split Log Levels Across Transports

Send errors to one destination and all logs to another:

```typescript
// All logs to file, errors to Sentry
const logger = IgniterLogger.create()
  .withLevel(IgniterLogLevel.Debug)
  .withAppName('api')
  .addTransport({
    target: 'file',
    options: { path: './logs/all.log' },
  })
  .addTransport({
    target: 'pino-sentry-transport',
    options: {
      dsn: process.env.SENTRY_DSN!,
      level: 'error', // only errors and above
    },
  })
  .build();
```
