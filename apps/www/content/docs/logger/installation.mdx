## Installation

`@igniter-js/logger` is a server-side package backed by Pino v9. The package manifest does not declare a minimum Node.js or Bun version; use a runtime supported by Pino and by the selected transport. The package bundles `pino`, `pino-pretty`, and `pino-abstract-transport` as direct dependencies.

<Tabs items={['npm', 'pnpm', 'yarn', 'bun']} groupId="package-manager">
  <Tab value="npm">
    ```bash
    npm install @igniter-js/logger
    ```
  </Tab>
  <Tab value="pnpm">
    ```bash
    pnpm add @igniter-js/logger
    ```
  </Tab>
  <Tab value="yarn">
    ```bash
    yarn add @igniter-js/logger
    ```
  </Tab>
  <Tab value="bun">
    ```bash
    bun add @igniter-js/logger
    ```
  </Tab>
</Tabs>

<Callout type="info">
  Pino, pino-pretty, and pino-abstract-transport are direct dependencies. The current package manifest does not declare `@igniter-js/common` as a production dependency, even though the Logger entry imports it at runtime for `IgniterLoggerError`. Install both packages explicitly: `npm install @igniter-js/logger @igniter-js/common`.
</Callout>

## Runtime Requirements

### Node.js

```json title="package.json"
{
  "engines": {
    "node": ">=18.0.0"
  }
}
```

Logger uses `pino` and `pino-pretty` internally. The **console transport** (default) works out of the box. The **file transport** uses Pino's `pino/file` target. The **HTTP transport** uses the global `fetch` API and `AbortSignal.timeout()`.

### Bun

```json title="package.json"
{
  "engines": {
    "bun": ">=1.0.0"
  }
}
```

The package does not declare a Bun version floor. The HTTP transport requires Bun's global `fetch` and `AbortSignal.timeout()`; the file transport is delegated to Pino's `pino/file` target.

<Callout type="warn">
  **Server-only:** The package's `browser` mapping resolves to a shim that throws an error. Do not import `@igniter-js/logger` from browser code; use `console.*` or a browser logging package instead.
</Callout>

## TypeScript Configuration

The package does not declare a TypeScript minimum version. For a modern Node.js project, a configuration such as this supports the package's ESM exports and strict type checking:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "strict": true,
    "moduleResolution": "bundler",
    "module": "ESNext",
    "target": "ES2022"
  }
}
```

The `"bundler"` module resolution lets TypeScript resolve `@igniter-js/logger` exports correctly from both ESM and CJS consumers.

## Dependencies

Logger ships with three direct dependencies:

| Package | Purpose | Version |
|---------|---------|---------|
| `pino` | Core logging engine | ^9.0.0 |
| `pino-pretty` | Console pretty-printing | ^13.0.0 |
| `pino-abstract-transport` | Custom HTTP transport worker | ^2.0.0 |

For **external transports** (Logtail, Datadog, Loki, etc.), install the corresponding package separately:

```bash
npm install @logtail/pino
# or
npm install pino-datadog-transport
```

## Verifying Installation

Create a minimal script to confirm everything works:

```typescript title="verify.ts"
import { IgniterLogger, IgniterLogLevel } from '@igniter-js/logger';

// Console transport (default)
const logger = IgniterLogger.create()
  .withLevel(IgniterLogLevel.Info)
  .withAppName('verify')
  .build();

logger.info('Logger is working');
logger.success('Installation verified');

// Flush and check
await logger.flush();
console.log('✅ @igniter-js/logger installed correctly');
```

Run it:

```bash
npx tsx verify.ts
```

You should see pretty-formatted log output with timestamps and a `✅` success message.
