## Event Validation Settings

The builder exposes `mode` (`"development" | "always" | "none"`) and `strict` options through `.withValidation()` and `.addEvents()`. These values are stored in builder configuration. The current `IgniterTelemetryManager.emit()` implementation does not read them and does not parse event attributes against registered schemas.

<Callout type="warn">
  Do not rely on `mode` or `strict` for runtime validation in this release. The exported error identifiers `TELEMETRY_UNKNOWN_EVENT` and `TELEMETRY_SCHEMA_VALIDATION_FAILED` are not raised by the current `emit()` path.
</Callout>

## What Event Registries Provide Today

`IgniterTelemetryEvents` stores schema descriptors and exposes inferred event names and attribute types to TypeScript. This catches many mistakes when the application is type-checked, but it does not validate values received from untyped input at runtime.

```typescript
import { IgniterTelemetry, IgniterTelemetryEvents } from "@igniter-js/telemetry";
import { LoggerTransportAdapter } from "@igniter-js/telemetry/adapters";
import { z } from "zod";

const PaymentEvents = IgniterTelemetryEvents
  .namespace("billing")
  .event("succeeded", z.object({ "ctx.payment.id": z.string() }))
  .build();

const telemetry = IgniterTelemetry.create()
  .addEvents(PaymentEvents)
  .addTransport(LoggerTransportAdapter.create({ logger: console }))
  .build();

// TypeScript infers the registered name and required attribute.
telemetry.emit("billing.succeeded", {
  attributes: { "ctx.payment.id": "pay_123" },
});
```

Validate untrusted input with your schema library before calling `emit()`:

```typescript
const parsed = z.object({ "ctx.payment.id": z.string() }).safeParse(input);
if (parsed.success) {
  telemetry.emit("billing.succeeded", { attributes: parsed.data });
}
```

## Configuration API

The settings remain available for configuration compatibility, but the current manager does not enforce them during event delivery. `.addEvents(descriptor, options)` merges options into builder-level settings; it does not keep independent validation settings per registry.

```typescript
const telemetry = IgniterTelemetry.create()
  .withValidation({ mode: "always", strict: true })
  .addEvents(PaymentEvents, { mode: "development" })
  .addTransport(LoggerTransportAdapter.create({ logger: console }))
  .build();
```

For current behavior and API details, see [Defining Events](/docs/telemetry/defining-events) and [Builder Configuration](/docs/telemetry/builder-config).
