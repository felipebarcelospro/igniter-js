## Troubleshooting

This guide covers the most common issues, their error codes, and step-by-step solutions.

---

## Error Code Reference

The package exports error-code identifiers, but not every declared code is currently raised by the runtime. Validation-related codes are not produced by `emit()`, and transport delivery errors are caught by its asynchronous path. Treat the tables as source-level identifiers, not a guarantee that each failure reaches the caller.

### Configuration

The builder defaults the service to `"igniter-app"` and environment to `"development"`. The corresponding `SERVICE_REQUIRED`, `ENVIRONMENT_REQUIRED`, and `CONFIGURATION_INVALID` identifiers are exported, but the current builder does not raise them for these defaults.

### Transport Errors

| Code | Cause | Solution |
|------|-------|----------|
| `TELEMETRY_INVALID_TRANSPORT` | Falsy transport passed to `.addTransport()` | Pass a valid adapter instance |
| `TELEMETRY_TRANSPORT_FAILED` | Internal error created when every adapter rejects; `emit()` catches it asynchronously | Inspect logs from `.withLogger()` and adapter-specific error handling |
| `TELEMETRY_TRANSPORT_INIT_FAILED` | Adapter `init()` rejects in a background promise started by `.build()` | Validate adapter setup before serving traffic; `.build()` does not await initialization |

### Event Errors

| Code | Cause | Solution |
|------|-------|----------|
| `TELEMETRY_INVALID_EVENT_NAME` | Event name is empty or contains spaces, colons, or a reserved prefix | Use a non-empty name without spaces or colons; dots are the convention for namespacing |

### Namespace Errors

| Code | Cause | Solution |
|------|-------|----------|
| `TELEMETRY_INVALID_NAMESPACE` | Namespace is empty or contains spaces or colons | Use a non-empty namespace without spaces or colons |
| `TELEMETRY_RESERVED_NAMESPACE` | Event or group name begins with `__` or `__internal` | Choose an event or group name without those reserved prefixes |
| `TELEMETRY_DUPLICATE_NAMESPACE` | Same namespace registered twice | Merge events into a single namespace or use different namespaces |

### Session Errors

| Code | Cause | Solution |
|------|-------|----------|
| `TELEMETRY_SESSION_ENDED` | Modifying or emitting after `.end()` | Create a new session if needed |

### Scope & Actor Errors

| Code | Cause | Solution |
|------|-------|----------|
| `TELEMETRY_DUPLICATE_SCOPE` | Same scope key added twice | Use unique scope keys |
| `TELEMETRY_DUPLICATE_ACTOR` | Same actor key added twice | Use unique actor keys |

## Common Issues

### 1. "No events are showing up in my transport"

**Symptom:** You call `telemetry.emit()` but nothing appears in logs/Sentry/Slack.

**Likely causes:**

- **Sampling is filtering events.** Check your sampling config — if `infoRate: 0.1`, only 10% of info events are sent.

```typescript
// Temporarily set all rates to 1.0 for debugging
.withSampling({ debugRate: 1.0, infoRate: 1.0, warnRate: 1.0, errorRate: 1.0 })
```

- **Event name matches a `never` pattern.** Check `never: ["health.check"]` — events with matching names are dropped.

- **Transport is filtering by level.** Check `minLevel` on Logger/Slack/Discord adapters.

```typescript
// Check: minLevel: "error" means debug/info/warn are dropped
LoggerTransportAdapter.create({ logger: console, minLevel: "debug" })
```

---

### 2. Events are not delivered to a transport

**Symptom:** Events are not delivered although `emit()` returned.

**Likely causes:**

- **Network issues.** HTTP/OTLP adapters can't reach their endpoints.
- **Invalid credentials.** Slack/Discord/Telegram webhook URLs are wrong or expired.
- **Sentry SDK not configured in the application.** Install and initialize the Sentry SDK used by your app, then pass its exported SDK object to the adapter.

**Solutions:**

1. Inspect adapter logs and test each transport individually — `emit()` returns `void` and does not expose asynchronous delivery errors
2. Check environment variables are set in the running process
3. Add a Logger transport as a fallback:

```typescript
.addTransport(LoggerTransportAdapter.create({ logger: console })) // Always works
.addTransport(HttpTransportAdapter.create({ url: "..." }))
```

---

### 3. "TELEMETRY_DUPLICATE_NAMESPACE — namespace already registered"

**Symptom:** Adding a second event descriptor with the same namespace throws.

**Fix:** Merge events into a single namespace:

```typescript
// ❌ Two separate registries with same namespace
const AuthLogin = IgniterTelemetryEvents
  .namespace("igniter.auth")
  .event("login.succeeded", schema)
  .build();

const AuthLogout = IgniterTelemetryEvents
  .namespace("igniter.auth")    // DUPLICATE!
  .event("logout", schema)
  .build();

// ✅ Single registry with all events
const AuthEvents = IgniterTelemetryEvents
  .namespace("igniter.auth")
  .event("login.succeeded", schema)
  .event("logout", schema)
  .build();
```

### 4. Validate untrusted event attributes

The current telemetry manager does not parse registered schemas at runtime. TypeScript catches mismatches in checked source, but values from requests, files, or other untyped inputs must be validated by application code before `emit()`:

```typescript
const parsed = orderSchema.safeParse(input);
if (!parsed.success) {
  return { ok: false, issues: parsed.error.issues };
}

telemetry.emit("igniter.orders.completed", {
  attributes: parsed.data,
});
```

---

### 5. "TELEMETRY_SESSION_ENDED — cannot modify session"

**Symptom:** Trying to call `.actor()`, `.scope()`, or `.emit()` on an ended session.

**Fix:** Sessions are single-use. Create a new one:

```typescript
// ❌ Reusing an ended session
const session = telemetry.session().actor("user", "usr_123");
await session.end();
session.emit("event", {});  // Throws!

// ✅ Create a new session
const newSession = telemetry.session().actor("user", "usr_123");
newSession.emit("event", {});
await newSession.end();
```

### 6 "Redaction isn't working — sensitive data still visible"

**Symptom:** You configured denylistKeys but passwords still appear in logs.

**Likely causes:**

- **Case mismatch.** Redaction is case-insensitive — but your key might use a different convention.
- **Nested data is not an event attribute value.** `IgniterTelemetryAttributes` accepts primitive values (including `null`), so flatten nested data into attribute keys before emitting.

```typescript
// ✅ Works — top-level key matched
attributes: {
  "ctx.auth.password": "s3cret!"   // Removed!
}

// ❌ Nested object values do not match IgniterTelemetryAttributes
attributes: { "ctx.auth": { password: "s3cret!" } }
```

**Fix:** Always flatten sensitive data to top-level attribute keys:

```typescript
// ✅ Flatten sensitive fields
attributes: {
  "ctx.auth.method": "password",
  "ctx.auth.password": "s3cret!",   // Will be redacted
}
```

### 7. "Telemetry is slowing down my application"

**Symptom:** High latency or throughput drops when telemetry is enabled.

**Likely causes:**

- **Too many transports.** Each transport processes every event.
- **Sync operations in transport.** Custom adapters with blocking code.
- **No sampling in production.** All debug/info events being processed.

**Solutions:**

1. Enable aggressive sampling in production (see [Sampling & Redaction](/docs/telemetry/sampling-redaction))
2. Reduce transport count to essentials
3. Use `minLevel` to filter noisy transports
4. Ensure custom transport `handle()` is async and non-blocking

## Debugging Checklist

When something isn't working, run through this checklist:

1. **Is `.build()` called?** The manager is only created after `.build()`.
2. **Is a transport added?** The builder accepts no transports; without one, events go nowhere.
3. **Are events being sampled out?** Set all rates to 1.0 temporarily.
4. **Are you relying on strict or schema validation?** These settings are not currently enforced by `emit()`; validate untrusted values in application code.
5. **Are environment variables set?** Check `process.env` for transport credentials.
6. **Is the logger configured?** Add `.withLogger(...)` to see internal telemetry logs.
7. **Is `shutdown()` called on exit?** This invokes adapter cleanup hooks but does not guarantee delivery of events already in flight.
