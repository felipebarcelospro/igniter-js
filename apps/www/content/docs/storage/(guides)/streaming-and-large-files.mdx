## Stream Reads

Use `stream` to pipe files directly from the adapter to HTTP responses or processing pipelines.

```typescript
const stream = await storage.stream("public/video.mp4");
stream.pipe(res);
```

Ensure your adapter/provider supports ranged requests if you need partial content; otherwise serve full streams.

## Large Uploads

The S3 adapter uses multipart uploads for Node streams. Always set or infer `contentType` for correct policies and downstream behavior. The max-size policy is enforced only when the manager can determine the stream size, so perform a preflight check when the source size is known.

```typescript
await storage.scope("public").upload(largeStream, "backups/db.dump");
```

<Callout type="info">
  If you need client-side chunking, keep that logic at the edge and hand a
  single stream or Blob to the storage manager. Policies still run before
  upload, and errors return `IGNITER_STORAGE_UPLOAD_FAILED` with the original
  cause.
</Callout>

## Retry and Backoff

Wrap uploads with retry logic for transient network failures, but avoid retrying policy violations. Typed errors expose `code` and `operation` so you can branch cleanly.

```typescript
import { IgniterStorageError } from "@igniter-js/storage";

async function uploadWithRetry(
  file: Blob,
  destination: string,
  maxRetries = 3,
) {
  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await storage.upload(file, destination);
    } catch (error) {
      if (
        !IgniterStorageError.is(error) ||
        error.code !== "IGNITER_STORAGE_UPLOAD_FAILED" ||
        attempt === maxRetries
      ) {
        throw error;
      }
      await new Promise((resolve) => setTimeout(resolve, attempt * 500));
    }
  }
}
```

See [Policies & Validation](</docs/storage/policies-and-validation>) for size/type guardrails and [File Operations](</docs/storage/file-operations>) for more lifecycle actions.
