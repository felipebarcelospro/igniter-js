## Mock Adapter for Unit Tests

Use the built-in mock adapter to avoid network calls. It implements the storage contract and stores data in memory, making it ideal for unit tests.

```typescript
import { IgniterStorage } from "@igniter-js/storage";
import { MockStorageAdapter } from "@igniter-js/storage/adapters";

const mock = MockStorageAdapter.create();
const storage = IgniterStorage.create()
  .withAdapter(mock)
  .withUrl("http://localhost:3000/cdn")
  .addScope("test", "/tests")
  .build();
```

Reset the adapter between tests to prevent bleed-over:

```typescript
afterEach(() => mock.clear());
```

## Local Emulators

- **S3 (MinIO/localstack)**: use an endpoint containing `localhost` (for example `http://localhost:9000`) if you need the adapter's built-in TLS check to disable TLS. The check is a string match; `127.0.0.1` does not match. Path-style addressing is enabled. Seed buckets before tests.
- **GCS**: the adapter currently constructs the official SDK client without forwarding a custom endpoint, so the `IGNITER_STORAGE_GOOGLE_ENDPOINT` setting does not connect it to an emulator. Use a real test bucket/project with isolated credentials, or a mock adapter for local tests.

## Fixtures and Cleanup

Use scoped managers to limit cleanup radius. Combine `list` + `delete` after each suite to keep fixtures small. Hooks fire during tests, so assert on emitted events to verify observability.

For troubleshooting common adapter errors, see [Troubleshooting](/docs/storage/troubleshooting). For production readiness, review [Policies & Validation](</docs/storage/policies-and-validation>).
