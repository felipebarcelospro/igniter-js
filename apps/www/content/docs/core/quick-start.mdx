## What you will build

This guide creates a small users API with a typed application context, a validated mutation, and a Fetch-compatible router.

## Install

~~~bash
npm install @igniter-js/core zod
~~~

## Configure Igniter

~~~typescript title="src/igniter.ts"
import { Igniter } from '@igniter-js/core'

type User = { id: string; name: string }

type AppContext = {
  users: Map<string, User>
}

export const igniter = Igniter.create()
  .withContext<AppContext>({ users: new Map() })
  .withConfig({ basePATH: '/api/v1' })
  .build()
~~~

withContext supplies the value available to each action handler. withConfig configures router settings such as basePATH. The builder is finalized with build().

## Define a controller

~~~typescript title="src/users.controller.ts"
import { z } from 'zod'
import { igniter } from './igniter'

export const usersController = igniter.controller({
  name: 'users',
  path: '/users',
  actions: {
    list: igniter.query({
      path: '/',
      handler: async ({ context, response }) => {
        return response.success({ users: [...context.users.values()] })
      },
    }),

    create: igniter.mutation({
      path: '/',
      method: 'POST',
      body: z.object({ name: z.string().min(1) }),
      handler: async ({ context, request, response }) => {
        const user = { id: crypto.randomUUID(), name: request.body.name }
        context.users.set(user.id, user)
        return response.created({ user })
      },
    }),
  },
})
~~~

A query defaults to GET. A mutation declares its HTTP method and can validate its body with a Standard Schema-compatible validator such as Zod.

## Build and run the router

~~~typescript title="src/server.ts"
import { igniter } from './igniter'
import { usersController } from './users.controller'

const router = igniter.router.create()
  .addController('users', usersController)
  .withHealthCheck('/health')
  .build()

await router.listen(3000)
~~~

The API is available under /api/v1/users, and the health check is at /api/v1/health.
