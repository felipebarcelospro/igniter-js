## Overview

Igniter.create() returns the builder for the core API. Configure it with with* methods, then call build() to get the factories for queries, mutations, controllers, procedures, and routers.

~~~typescript
import { Igniter } from '@igniter-js/core'

type AppContext = {
  db: {
    findUser(id: string): Promise<{ id: string; name: string } | null>
    listUsers(): Promise<{ id: string; name: string }[]>
  }
}

// Replace this in-memory example with your database client.
const db: AppContext['db'] = {
  findUser: async (id) => ({ id, name: 'Ada' }),
  listUsers: async () => [{ id: '1', name: 'Ada' }],
}

export const igniter = Igniter.create()
  .withContext(() => ({ db }))
  .withConfig({ basePATH: '/api/v1' })
  .build()
~~~

`withContext()` needs a runtime object or factory for request handlers to receive values. A type-only call such as `withContext<AppContext>()` adds type information but does not create a database connection or other runtime services. Replace the in-memory `db` above with your application's database client.

## Configure context

Use a value when the context can be shared by the application:

~~~typescript
const igniter = Igniter.create()
  .withContext({ db })
  .build()
~~~

Use a factory when the context is created asynchronously:

~~~typescript
// Implement connectDatabase() using your database driver.
const igniter = Igniter.create()
  .withContext(async () => ({
    db: await connectDatabase(),
  }))
  .build()
~~~

Action handlers receive the resolved context as context. See [Context](/docs/core/context) for request-aware context patterns.

## Configure router settings

withConfig() accepts the core router configuration, including basePATH and baseURL.

~~~typescript
const igniter = Igniter.create()
  .withContext<AppContext>()
  .withConfig({
    basePATH: '/api/v1',
    baseURL: 'https://api.example.com',
  })
  .build()
~~~

## Add optional integrations

The builder also exposes integration methods. Use each only when the application needs it.

~~~typescript
const igniter = Igniter.create()
  .withContext<AppContext>()
  .withStore(storeManager)
  .withLogger(logger)
  .withTelemetry(telemetryManager)
  .addPlugin('auth', authPlugin)
  .build()
~~~

- withStore() attaches a Store manager for caching, events, and related core integrations.
- withLogger() attaches a logger.
- withTelemetry() attaches a telemetry manager.
- addPlugin(key, plugin) registers a plugin under a typed key.
- withStudio() attaches an Igniter Studio handler.

These methods are implemented by the core builder in [builder.service.ts](https://github.com/felipebarcelospro/igniter-js/blob/main/packages/core/src/services/builder.service.ts).

## Create the router

After build(), define actions and controllers, then use the router builder to register controllers.

~~~typescript
const usersController = igniter.controller({
  name: 'users',
  path: '/users',
  actions: {
    list: igniter.query({
      path: '/',
      handler: async ({ context, response }) =>
        response.success({ users: await context.db.listUsers() }),
    }),
  },
})

const router = igniter.router.create()
  .addController('users', usersController)
  .withHealthCheck('/health')
  .build()
~~~

The router handles Fetch Request objects and can be mounted in supported frameworks or started with router.listen(). See [Router](/docs/core/router) for server integration.
