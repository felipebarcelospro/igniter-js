## What a procedure does

A procedure runs before an action. It can return extra context for the action or return a response early. The current `igniter.procedure()` API is the legacy options-and-context API: its handler receives `(options, ctx)`. The procedure factory returned by `igniter.procedure()` takes those options and belongs in an action's `use` array.

## Create an authentication procedure

```typescript
import { Igniter } from "@igniter-js/core";

const db = makeDatabase();
const verifyToken = async (token: string): Promise<User | null> => lookupUserFromToken(token);

const igniter = Igniter.create()
  .withContext(async () => ({ db, verifyToken }))
  .build();

const authProcedure = igniter.procedure({
  name: "auth",
  handler: async (
    options: { required: boolean },
    { context, request, response },
  ) => {
    const token = request.headers.get("authorization");
    const user = token ? await context.verifyToken(token) : null;

    if (!user && options.required) {
      return response.unauthorized("Authentication required");
    }

    return { currentUser: user };
  },
});

const usersController = igniter.controller({
  path: "/users",
  actions: {
    me: igniter.query({
      path: "/me",
      use: [authProcedure({ required: true })],
      handler: async ({ context, response }) => {
        return response.success({ user: context.currentUser });
      },
    }),
  },
});
```

The procedure returns `{ currentUser }`; Core merges that object into the context passed to the action. When a procedure returns a response, Core stops the middleware chain and returns that response.

<Callout type="warn" title="Use the handler signature Core exposes">
  A procedure configured through `igniter.procedure()` must declare an options argument and a second context argument. Do not destructure the enhanced one-argument context shape here; it is not wired to this builder method.
</Callout>

## Reuse a procedure without options

The options factory can be called without arguments when the handler does not need options:

```typescript
const requestIdProcedure = igniter.procedure({
  name: "request-id",
  handler: (_options: Record<string, never>, { request }) => ({
    requestId: request.headers.get("x-request-id") ?? crypto.randomUUID(),
  }),
});

const healthController = igniter.controller({
  path: "/health",
  actions: {
    check: igniter.query({
      path: "/",
      use: [requestIdProcedure()],
      handler: async ({ context, response }) =>
        response.success({ status: "ok", requestId: context.requestId }),
    }),
  },
});
```

## Early responses

Use the response helpers with string messages. An early response prevents the action from running:

```typescript
const requireApiKey = igniter.procedure({
  name: "api-key",
  handler: (
    _options: Record<string, never>,
    { request, response },
  ) => {
    if (!request.headers.get("x-api-key")) {
      return response.unauthorized("API key required");
    }

    return {};
  },
});
```

You can attach the procedure to an individual action with `use: [requireApiKey()]`. Procedures can also be configured as router-level middleware with the router builder's `.addMiddleware()` method when every route should share them; keep route-specific authorization on the relevant actions.

## Enhanced procedure utilities

Core also exports `createEnhancedProcedureBuilder()` and `createEnhancedProcedureFactories()` from `@igniter-js/core`. These standalone helpers produce the enhanced one-argument handler shape, but the current `igniter.procedure()` method does not call them. Use the builder/factory directly only when you have verified how the resulting `IgniterProcedure` is integrated into your application.

For action construction and context typing, continue to [Actions](</docs/core/actions>) and [Context](</docs/core/context>).
