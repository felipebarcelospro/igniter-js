title: React Integration
description: Use Caller’s React hooks for queries, mutations, cache updates, and session-aware requests.
---

The React client is an optional entry point at `@igniter-js/caller/client`. It adds a provider-managed cache and hooks without adding a React dependency to the core HTTP client.

## Install and provide Caller

Install React and Caller, then create the HTTP manager once in a module:

```ts title="lib/api.ts"
import { IgniterCaller } from '@igniter-js/caller'

export const api = IgniterCaller.create()
  .withBaseUrl('https://api.example.com')
  .build()
```

Wrap the React tree with one Caller manager:

```tsx title="app/providers.tsx"
import { IgniterCallerProvider } from '@igniter-js/caller/client'
import { api } from '@/lib/api'

export function Providers({ children }: { children: React.ReactNode }) {
  return <IgniterCallerProvider caller={api}>{children}</IgniterCallerProvider>
}
```

Create a typed hook in a client module:

```ts title="lib/use-api.ts"
import { useIgniterCaller } from '@igniter-js/caller/client'
import type { api } from './api'

export const useApi = () => useIgniterCaller<typeof api>()
```

## Queries

Call `.useQuery()` on a GET operation. The hook returns `data`, `error`, loading/status flags, `refetch`, and `invalidate`.

```tsx
'use client'

import { useApi } from '@/lib/use-api'

export function UserList() {
  const api = useApi()
  const { data, error, isLoading, refetch } = api.get('/users').useQuery({
    staleTime: 30_000,
    refetchOnWindowFocus: true,
  })

  if (isLoading) return <p>Loading users…</p>
  if (error) return <p>Could not load users: {error.message}</p>

  return (
    <section>
      <button onClick={refetch}>Refresh</button>
      <pre>{JSON.stringify(data, null, 2)}</pre>
    </section>
  )
}
```

The options include `enabled`, `initialData`, `params`, `query`, `headers`, `cookies`, `staleTime`, `gcTime`, polling and focus/refetch settings, `select`, and lifecycle callbacks. See the exported `IgniterCallerClientUseQueryOptions` type for the full list.

## Mutations

Use `.useMutation()` on a POST, PUT, PATCH, or DELETE operation. Pass request values to `mutate` or `mutateAsync` according to the operation’s inferred variables.

```tsx
'use client'

import { useApi } from '@/lib/use-api'

export function CreateUserButton() {
  const api = useApi()
  const users = api.get('/users')
  const { mutate, isLoading, error } = api.post('/users').useMutation({
    onSuccess: () => users.invalidate(),
  })

  return (
    <div>
      <button
        disabled={isLoading}
        onClick={() => mutate({ body: { name: 'Ada' } })}
      >
        Create user
      </button>
      {error && <p>{error.message}</p>}
    </div>
  )
}
```

For schema-derived operation trees, add `operationId` metadata to your Caller schemas; otherwise the client supports path-based calls such as `api.get('/users')`.

## Cache operations

Each query operation exposes `invalidate(data?)`, `getQueryData()`, and `setQueryData(updater, variables?)`. Invalidation clears matching provider cache entries and notifies active observers. You can also call `api.reset({ scope: 'cache' })` to clear the provider cache and refetch observers.

```tsx
const users = api.get('/users')
users.setQueryData((previous) => previous ?? [])
users.invalidate()
```

## Session and runtime request state

Configure session resolution and persistence on `IgniterCallerProvider`; see [Session, Request State, and Persistence](/docs/caller/client-state). The provider accepts a single `caller` prop. It does not accept a map of named callers.
