---
title: Caller Manager
description: Use the built Caller manager to issue requests, batch promises, observe responses, and invalidate cached entries.
---

`IgniterCaller.create().build()` returns an `IgniterCallerManager`. The manager owns the client configuration and creates request builders for each call.

```ts
import { IgniterCaller } from '@igniter-js/caller'

export const api = IgniterCaller.create()
  .withBaseUrl('https://api.example.com')
  .build()
```

## Request methods

The manager provides `get`, `post`, `put`, `patch`, `delete`, `head`, `options`, and `request`. The verb helpers return a fluent request builder; `.execute()` performs the request.

```ts
const result = await api.get('/users/:id')
  .params({ id: '42' })
  .execute()

if (result.error) {
  console.error(result.error.code, result.error.message)
} else {
  console.log(result.data)
}
```

See [Request Builder](/docs/caller/builder) for request configuration and [HTTP Methods](/docs/caller/methods) for method behavior.

## Batch independent requests

`IgniterCallerManager.batch()` is a static helper that awaits a tuple of request promises with `Promise.all` semantics. The returned tuple preserves result order and types.

```ts
import { IgniterCaller, IgniterCallerManager } from '@igniter-js/caller'

const api = IgniterCaller.create().withBaseUrl('https://api.example.com').build()
const [users, posts] = await IgniterCallerManager.batch([
  api.get('/users').execute(),
  api.get('/posts').execute(),
] as const)
```

A rejected promise rejects the batch, as with `Promise.all`; handle expected HTTP failures through each Caller result's `error` field.

## Observe matching responses

`IgniterCallerManager.on(pattern, callback)` registers a global listener for matching request URLs. The callback receives the API response result and `{ url, method, timestamp }`. The returned function unsubscribes that listener. `off(pattern, callback?)` can also remove listeners.

```ts
const unsubscribe = IgniterCallerManager.on(/^https:\/\/api\.example\.com\/users/, (result, context) => {
  console.log(context.method, context.url, result.status)
})

// When the listener is no longer needed:
unsubscribe()
```

The pattern is a string or `RegExp`, not a named event such as `'response'`. The manager emits completed response results; it does not expose separate request/error/cache event names through this API.

## Invalidate cached entries

Static `invalidate(key)` deletes one key from the in-memory cache and configured store. `invalidatePattern(pattern)` clears matching in-memory entries only; a persistent store does not support pattern deletion through this API, so clean those entries through the store's own interface. Await these methods when code needs to wait for cache clearing to finish.

```ts
await api.post('/users').body({ name: 'Ada' }).execute()
await IgniterCallerManager.invalidate('/users')

// Clear related keys when your app uses a stable key convention.
await IgniterCallerManager.invalidatePattern('/users/*')
```

Request cache behavior is configured with `.stale(milliseconds)` and `.cache(requestCache, key?)`; see [Caching](/docs/caller/caching). Cache key conventions depend on your request URL and any explicit key you provide.
