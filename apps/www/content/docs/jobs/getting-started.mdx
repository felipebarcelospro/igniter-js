This guide walks you through installing `@igniter-js/jobs`, defining a queue with jobs and cron tasks, creating the jobs runtime, dispatching your first job, and starting a worker. By the end, you'll have a fully working background job system.

## Prerequisites

- **Node.js 18+** or **Bun 1.0+**
- **Redis** (if using the BullMQ adapter) — running locally or via a cloud provider
- Basic familiarity with TypeScript and Zod schemas

<Callout type="info" title="Quick Start Without Redis">
  Use the **in-memory adapter** for development and testing — no external dependencies required.
  Import it from `@igniter-js/jobs/adapters/mock`.
</Callout>

If you're using the BullMQ adapter, create a Redis client:

```typescript

export const redis = new Redis(
  process.env.REDIS_URL || 'redis://localhost:6379'
)
```

<Callout type="info" title="Skip This For Development">
  For local development, use the in-memory adapter: `IgniterJobsMemoryAdapter.create()` — no Redis needed.
</Callout>

## Step 3: Define Your First Queue

Create a queue with jobs and an optional cron task using `IgniterQueue`:

```typescript
// src/jobs/email.queue.ts
import { IgniterQueue } from '@igniter-js/jobs'
import { z } from 'zod'

export const emailQueue = IgniterQueue.create('email')
  .addJob('sendWelcome', {
    input: z.object({
      email: z.string().email(),
      name: z.string(),
    }),
    handler: async ({ input, context }) => {
      console.log(`Sending welcome email to ${input.email}`)
      await context.emailService.sendWelcome(input.email, input.name)
    },
  })
  .addJob('sendPasswordReset', {
    input: z.object({
      email: z.string().email(),
      token: z.string(),
    }),
    handler: async ({ input, context }) => {
      await context.emailService.sendPasswordReset(input.email, input.token)
    },
  })
  .addCron('dailyCleanup', {
    cron: '0 2 * * *', // Every day at 2 AM
    handler: async ({ context }) => {
      await context.emailService.cleanupOldRecords()
    },
  })
  .build()
```

<Callout type="info" title="Type Inference">
  TypeScript infers the input type from your Zod schema. Inside the handler, `input.email` and `input.name` are fully typed — no manual type annotations needed.
</Callout>

## Step 4: Create the Jobs Runtime

Use `IgniterJobs.create()` with the fluent builder to configure and build your jobs runtime:

```typescript
// src/services/jobs.ts
import { IgniterJobs } from '@igniter-js/jobs'
import { IgniterJobsBullMQAdapter } from '@igniter-js/jobs/adapters/node'
import { redis } from '@/lib/redis'
import { emailQueue } from '@/jobs/email.queue'

export const jobs = IgniterJobs.create()
  .withAdapter(IgniterJobsBullMQAdapter.create({ redis }))
  .withService('my-api')
  .withEnvironment(process.env.NODE_ENV || 'development')
  .withContext(async () => ({
    emailService: new EmailService(),
  }))
  .addQueue(emailQueue)
  .build()
```

<Callout type="warn" title="Required Builder Methods">
  All four methods — `withAdapter()`, `withService()`, `withEnvironment()`, and `withContext()` — are **required** before calling `build()`. The builder will throw a descriptive error if any are missing.
</Callout>

### Using the In-Memory Adapter

For development and testing, swap the adapter:

```typescript
import { IgniterJobsMemoryAdapter } from '@igniter-js/jobs/adapters/mock'

const jobs = IgniterJobs.create()
  .withAdapter(IgniterJobsMemoryAdapter.create())
  .withService('my-api')
  .withEnvironment('development')
  .withContext(async () => ({ emailService: new EmailService() }))
  .addQueue(emailQueue)
  .build()
```

### Adding Multiple Queues

Register all your queues during the build phase:

```typescript
import { emailQueue } from '@/jobs/email.queue'
import { analyticsQueue } from '@/jobs/analytics.queue'
import { paymentQueue } from '@/jobs/payment.queue'

const jobs = IgniterJobs.create()
  .withAdapter(...)
  .withService('my-api')
  .withEnvironment('production')
  .withContext(async () => ({ db, emailService, paymentService }))
  .addQueue(emailQueue)
  .addQueue(analyticsQueue)
  .addQueue(paymentQueue)
  .build()
```

## Step 5: Dispatch a Job

Dispatch jobs from anywhere in your application — API routes, server actions, event handlers:

```typescript
// src/features/users/actions/register.ts
import { jobs } from '@/services/jobs'

export async function registerUser(userData: { email: string; name: string }) {
  // Create the user in your database...
  const user = await db.user.create({ data: userData })

  // Dispatch the welcome email job
  const jobId = await jobs.email.sendWelcome.dispatch({
    input: {
      email: user.email,
      name: user.name,
    },
  })

  console.log(`Welcome email job dispatched: ${jobId}`)
  return user
}
```

### Dispatch with Options

Control priority, delay, attempts, and more:

```typescript
await jobs.email.sendWelcome.dispatch({
  input: { email: 'user@example.com', name: 'Alice' },
  priority: 10,           // Higher priority jobs processed first
  delay: 5000,            // Delay execution by 5 seconds
  attempts: 5,            // Retry up to 5 times on failure
  jobId: 'custom-job-id', // Custom job identifier
  metadata: {             // Custom metadata for search/filtering
    source: 'signup-flow',
  },
})
```

## Step 6: Start a Worker

Workers process jobs from queues. Create one with the fluent worker builder:

```typescript
// src/workers/start.ts
import { jobs } from '@/services/jobs'

const emailWorker = await jobs.worker.create()
  .addQueue('email')
  .withConcurrency(5)
  .onActive(({ job }) => {
    console.log(`Processing ${job.name} (${job.id})`)
  })
  .onSuccess(({ job, result }) => {
    console.log(`Completed ${job.name}:`, result)
  })
  .onFailure(({ job, error }) => {
    console.error(`Failed ${job.name}:`, error.message)
  })
  .start()

console.log('Worker started:', emailWorker.id)
```

### Auto-Start Workers

Alternatively, configure workers to start automatically when `build()` is called:

```typescript
const jobs = IgniterJobs.create()
  .withAdapter(IgniterJobsBullMQAdapter.create({ redis }))
  .withService('my-api')
  .withEnvironment('production')
  .withContext(async () => ({ emailService }))
  .addQueue(emailQueue)
  .withAutoStartWorker({
    queues: ['email'],
    concurrency: 5,
  })
  .build()
// Worker starts automatically — no manual start() call needed
```

## Troubleshooting

### Jobs Not Processing

**Problem**: Jobs are dispatched but never execute.

**Solutions**:
- Verify a worker is running for the queue — check logs for `"Worker started"`
- Ensure the worker's `addQueue('email')` matches the queue name exactly
- Check Redis connectivity with `redis-cli ping`

### Redis Connection Errors

**Problem**: `ECONNREFUSED` when using the BullMQ adapter.

**Solutions**:
- Ensure Redis is running: `redis-cli ping` should return `PONG`
- Verify your `REDIS_URL` environment variable
- For local development, switch to the in-memory adapter

### TypeScript Errors

**Problem**: TypeScript can't find adapter imports.

**Solutions**:
- BullMQ adapter: use `@igniter-js/jobs/adapters/node`
- Memory adapter: use `@igniter-js/jobs/adapters/mock`
- Bun SQLite adapter: use `@igniter-js/jobs/adapters/bun`

### Builder Validation Errors

**Problem**: `build()` throws `JOBS_ADAPTER_REQUIRED` or similar.

**Solution**: Ensure all four required methods are called:
`withAdapter()` → `withService()` → `withEnvironment()` → `withContext()` → `build()`
