Igniter.js Jobs supports a spectrum of scheduling: immediate dispatch, delayed execution, scheduled at-a-specific-time, and recurring cron-based patterns. Every scheduling option is type-safe and validated at runtime.

## Immediate Dispatch

The simplest form — fire and forget:

```typescript
const jobId = await jobs.email.sendWelcome.dispatch({
  input: { email: 'user@example.com', name: 'Alice' },
})
```

Returns a `string` — the job ID for tracking.

---

## Delayed Dispatch

Add a delay (in milliseconds) to run the job after a waiting period:

```typescript
// Run after 30 seconds
await jobs.email.sendReminder.dispatch({
  input: { userId: '123' },
  delay: 30_000,
})

// Run after 1 hour
await jobs.analytics.generateReport.dispatch({
  input: { reportType: 'daily' },
  delay: 3_600_000,
})
```

---

## Schedule at a Specific Time

Use `.schedule()` with the `at` option to run at an exact date/time:

```typescript
await jobs.email.sendCampaign.schedule({
  input: { campaignId: 'summer-sale' },
  at: new Date('2025-07-01T10:00:00Z'), // July 1st, 10 AM UTC
})
```

<Callout type="warn" title="Future Dates Only">
  The `at` option must be a date in the future. Scheduling for a past date will throw an error.
</Callout>

---

## Repeating Jobs

Use `.schedule()` for one-off jobs that repeat. Define the repeat pattern inline:

### Repeat Every N Milliseconds

```typescript
await jobs.analytics.healthCheck.schedule({
  input: {},
  every: 60_000, // Every 60 seconds
})
```

### Cron-Based Recurrence

```typescript
await jobs.maintenance.cleanup.schedule({
  input: {},
  cron: '0 2 * * *',  // Every day at 2 AM
  tz: 'America/New_York',
})
```

### Limited Recurrence

```typescript
await jobs.notifications.sendReminder.schedule({
  input: { campaignId: 'onboarding' },
  cron: '0 9 * * *',    // Every day at 9 AM
  maxExecutions: 7,      // Run 7 times total (one week)
  tz: 'America/New_York',
})
```

<Callout type="info" title="schedule() vs addCron()">
  Use `.schedule()` for ad-hoc recurring jobs dispatched from application code. Use `.addCron()` on the queue builder for **persistent** cron jobs that are part of your queue definition and always registered with the adapter.
</Callout>

---

## Scheduling Options

All scheduling options available on `.schedule()`:

| Option | Type | Description |
|--------|------|-------------|
| `at` | `Date` | Run at a specific date/time (one-time) |
| `delay` | `number` | Delay in milliseconds before execution |
| `cron` | `string` | Cron expression for repeating jobs |
| `every` | `number` | Repeat every N milliseconds (mutually exclusive with `cron`) |
| `maxExecutions` | `number` | Maximum number of executions for repeating jobs |
| `tz` | `string` | Timezone for cron expression (e.g., `'America/New_York'`) |
| `skipWeekends` | `boolean` | Skip execution on Saturday and Sunday |
| `onlyBusinessHours` | `boolean` | Only execute during business hours |
| `businessHours` | `{ start, end, timezone? }` | Business hour range (24h format) |
| `onlyWeekdays` | `number[]` | Only execute on these weekdays (0=Sunday..6=Saturday) |
| `skipDates` | `Array<string \| Date>` | Dates to skip execution |
| `startDate` | `Date` | When to start the schedule |
| `endDate` | `Date` | When to end the schedule |

## Business Hours Scheduling

Run jobs only during business hours:

```typescript
await jobs.notifications.sendAlert.schedule({
  input: { userId: '123', message: 'Reminder' },
  cron: '0 * * * *',           // Every hour
  onlyBusinessHours: true,
  businessHours: {
    start: 9,                   // 9 AM
    end: 17,                    // 5 PM
    timezone: 'America/New_York',
  },
})
```

### Skip Weekends

```typescript
await jobs.reports.generateDaily.schedule({
  input: {},
  cron: '0 9 * * *',     // Every day at 9 AM
  skipWeekends: true,      // Skip Saturday and Sunday
})
```

### Specific Weekdays

```typescript
await jobs.reports.weeklySummary.schedule({
  input: {},
  cron: '0 9 * * *',           // Daily at 9 AM
  onlyWeekdays: [1, 3, 5],     // Monday, Wednesday, Friday only
})
```

### Skip Specific Dates

```typescript
await jobs.marketing.sendCampaign.schedule({
  input: { campaignId: 'holiday-sale' },
  cron: '0 10 * * *',
  skipDates: [
    '2025-12-25',  // Christmas
    new Date('2025-01-01'), // New Year's
  ],
})
```

## Cron Jobs on Queue Definitions

For persistent, always-registered cron jobs, use `.addCron()` on the queue builder:

```typescript
const maintenanceQueue = IgniterQueue.create('maintenance')
  .addJob('cleanup', {
    handler: async ({ context }) => {
      await context.db.cleanup()
    },
  })
  .addCron('dailyBackup', {
    cron: '0 3 * * *',            // Every day at 3 AM
    tz: 'America/New_York',
    handler: async ({ context }) => {
      await context.db.backup()
      return { backedUp: true }
    },
  })
  .addCron('weeklyReport', {
    cron: '0 9 * * 1',            // Every Monday at 9 AM
    onlyWeekdays: [1],
    handler: async ({ context }) => {
      const report = await context.reports.generateWeekly()
      await context.mailer.send(report)
    },
  })
  .build()
```

### Cron Definition Properties

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `cron` | `string` | **Yes** | Cron expression (5 or 6 fields) |
| `handler` | `(ctx) => Promise<TResult>` | **Yes** | Handler function |
| `tz` | `string` | No | Timezone for cron evaluation |
| `maxExecutions` | `number` | No | Maximum number of executions |
| `skipWeekends` | `boolean` | No | Skip Saturday and Sunday |
| `onlyBusinessHours` | `boolean` | No | Only during business hours |
| `businessHours` | `{ start, end, timezone? }` | No | Business hour range |
| `onlyWeekdays` | `number[]` | No | Restricted weekdays (0-6) |
| `skipDates` | `Array<string \| Date>` | No | Dates to skip |
| `startDate` | `Date` | No | Schedule start date |
| `endDate` | `Date` | No | Schedule end date |

<Callout type="info" title="Cron Handler Context">
  Unlike job handlers, cron handlers receive `context` without `input` — there's no input payload for scheduled cron tasks.
</Callout>

## Cron Expression Guide

Cron expressions follow the format: `minute hour day month weekday [year]`

```
┌───────────── minute (0–59)
│ ┌───────────── hour (0–23)
│ │ ┌───────────── day of month (1–31)
│ │ │ ┌───────────── month (1–12)
│ │ │ │ ┌───────────── day of week (0–6) (Sunday to Saturday)
│ │ │ │ │
* * * * *
```

**Common patterns:**

| Expression | Meaning |
|------------|---------|
| `0 * * * *` | Every hour at minute 0 |
| `0 9 * * *` | Every day at 9 AM |
| `0 0 * * 0` | Every Sunday at midnight |
| `0 0 1 * *` | First day of every month |
| `*/5 * * * *` | Every 5 minutes |
| `0 9-17 * * 1-5` | Every hour, 9 AM–5 PM, Monday–Friday |
| `0 0 1,15 * *` | 1st and 15th of every month |
| `0 8,12,18 * * *` | Daily at 8 AM, 12 PM, and 6 PM |

## Real-World Examples

### Daily Report at End of Business Day

```typescript
await jobs.reports.generateDaily.schedule({
  input: {},
  cron: '0 23 * * *',       // 11 PM daily
  tz: 'America/New_York',
})
```

### Hourly Health Check During Business Hours

```typescript
await jobs.monitoring.healthCheck.schedule({
  input: {},
  cron: '0 * * * *',          // Every hour
  onlyBusinessHours: true,
  businessHours: { start: 9, end: 17 },
  tz: 'America/New_York',
})
```

### One-Time Scheduled Reminder

```typescript
const reminderDate = new Date()
reminderDate.setHours(reminderDate.getHours() + 24)

await jobs.email.sendReminder.schedule({
  input: { userId: '123', type: 'trial-expiring' },
  at: reminderDate,
})
```

### Weekly Cleanup with Skip Dates

```typescript
await jobs.maintenance.weeklyCleanup.schedule({
  input: {},
  cron: '0 3 * * 0',           // Sunday at 3 AM
  skipDates: ['2025-12-28'],    // Skip holiday week
  tz: 'UTC',
})
```

## Best Practices

- **Always specify timezones** for cron schedules — server timezones are unpredictable
- **Set maxExecutions** for one-off recurring jobs to prevent infinite loops
- **Use `skipIfRunning` patterns** — consider job deduplication for long-running cron jobs
- **Validate cron expressions** — test with an online validator before deploying
- **Separate ad-hoc from persistent** — use `.schedule()` for dynamic, `.addCron()` for infrastructure
