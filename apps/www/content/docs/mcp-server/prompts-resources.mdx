## Prompts

Prompts return MCP messages and can accept arguments validated from a Zod raw shape. The prompt callback receives its typed arguments and an <code>McpContext</code> built from the router request context.

<Callout type="warn" title="Multiple prompt registration limitation">
  The current adapter implementation registers every configured prompt once for each prompt in the list. A single custom prompt can be registered; configuring several prompts causes duplicate registration attempts. Keep the list to one prompt until the implementation is corrected.
</Callout>

### Add one prompt

~~~typescript
import { IgniterMcpServer } from '@igniter-js/adapter-mcp-server';
import { z } from 'zod';
import { AppRouter } from '@/igniter.router';

const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .addPrompt({
    name: 'summarizeUser',
    description: 'Prepare a user summary from the supplied ID',
    args: { userId: z.string().uuid() },
    handler: async ({ userId }, context) => ({
      messages: [{
        role: 'user',
        content: {
          type: 'text',
          text: 'Summarize user ' + userId + '.',
        },
      }],
    }),
  })
  .build();

export const GET = handler;
export const POST = handler;
~~~

For the function API, provide the prompt in <code>prompts.custom</code>:

~~~typescript
const { server } = createMcpAdapter({
  router: AppRouter,
  prompts: {
    custom: [{
      name: 'summarizeUser',
      description: 'Prepare a user summary from the supplied ID',
      args: { userId: z.string().uuid() },
      handler: async ({ userId }, context) => ({
        messages: [{
          role: 'user',
          content: { type: 'text', text: 'Summarize user ' + userId + '.' },
        }],
      }),
    }],
  },
});

export const GET = server;
export const POST = server;
~~~

## Resources

Resources use the MCP SDK's <code>ReadResourceCallback</code> signature: the first argument is a <code>URL</code>, followed by request metadata. It is not the router's <code>McpContext</code>. The adapter's current <code>McpResource</code> contract contains only <code>name</code>, <code>uri</code>, and <code>handler</code>; registration does not forward resource description or MIME metadata. Put a MIME type on each returned content item when needed.

### Register a resource

~~~typescript
import { IgniterMcpServer } from '@igniter-js/adapter-mcp-server';
import { AppRouter } from '@/igniter.router';

const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .addResource({
    name: 'Application Settings',
    uri: 'config://app/settings',
    handler: async (uri) => {
      const settings = await loadPublicSettings();
      return {
        contents: [{
          uri: uri.href,
          mimeType: 'application/json',
          text: JSON.stringify(settings),
        }],
      };
    },
  })
  .build();

export const GET = handler;
export const POST = handler;
~~~

The function API accepts the same resource definition under <code>resources.custom</code>:

~~~typescript
const { server } = createMcpAdapter({
  router: AppRouter,
  resources: {
    custom: [{
      name: 'Application Settings',
      uri: 'config://app/settings',
      handler: async (uri) => ({
        contents: [{
          uri: uri.href,
          mimeType: 'application/json',
          text: JSON.stringify(await loadPublicSettings()),
        }],
      }),
    }],
  },
});
~~~
