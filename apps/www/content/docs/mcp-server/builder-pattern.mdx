## Overview

`IgniterMcpServer` configures a router-backed MCP handler through chainable methods. Use it when you want configuration grouped by purpose and TypeScript inference from your router.

## Create a handler

```typescript
import { IgniterMcpServer } from '@igniter-js/adapter-mcp-server';
import { AppRouter } from '@/igniter.router';

const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .withServerInfo({ name: 'Acme API', version: '1.0.0' })
  .withInstructions('Use the available tools to manage users.')
  .build();

export const GET = handler;
export const POST = handler;
```

## Configure the router tools

Router actions are exposed as tools by default. Filter by controller/action path when you want to limit exposure:

```typescript
const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .withToolFilter(['users.delete', 'admin.resetPassword'], 'exclude')
  .withToolTransform((controller, action, actionConfig) => ({
    name: `${controller}_${action}`,
    description: actionConfig.description ?? `Run ${controller}.${action}`,
    // Omit schema to retain generated body, query, and path inputs.
  }))
  .build();
```

The transform must return a tool configuration; returning `null` does not filter an action. The callback's action config provides `description`, `method`, and `path`; it has no `tags` or `summary` property. See [Advanced Configuration](/docs/mcp-server/advanced).

## Add a custom tool

Custom tools use a Zod raw shape for arguments and return an MCP tool result:

```typescript
import { z } from 'zod';

const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .addTool({
    name: 'calculateTax',
    description: 'Calculate tax for an amount in USD.',
    args: {
      amount: z.number().positive(),
      rate: z.number().min(0).max(1),
    },
    handler: async ({ amount, rate }) => ({
      content: [{ type: 'text', text: (amount * rate).toFixed(2) }],
    }),
  })
  .build();
```

## Add prompts and resources

The builder provides `addPrompt` and `addResource`. The current prompt registration implementation supports one configured prompt; multiple prompts can result in repeated registrations. A resource definition accepts `name`, `uri`, and `handler`. Its callback receives `(uri: URL, extra)` and returns an MCP resource result. The adapter does not forward resource description or MIME metadata. See [Prompts and Resources](/docs/mcp-server/prompts-resources) for details.

## Configure OAuth

`verifyToken` returns the MCP SDK `AuthInfo` shape when a token is valid and `undefined` otherwise:

```typescript
const { handler, auth } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .withOAuth({
    issuer: process.env.OAUTH_ISSUER!,
    scopes: ['mcp:read'],
    verifyToken: async ({ bearerToken }) => {
      const claims = await verifyJWT(bearerToken);
      if (!claims) return undefined;
      return {
        token: bearerToken,
        clientId: claims.clientId,
        scopes: claims.scopes,
        extra: { subject: claims.sub },
      };
    },
  })
  .build();

export const GET = handler;
export const POST = handler;
export const OPTIONS = auth.cors;
```

OAuth verification runs only when `verifyToken` is configured. `AuthInfo` is not automatically injected into your Igniter router context. See [OAuth](/docs/mcp-server/oauth).

## Observe tool execution

The adapter invokes these hooks for router-mapped tool execution:

```typescript
const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .withEvents({
    onToolCall: async (toolName) => logger.info('MCP tool started', { toolName }),
    onToolSuccess: async (toolName, result, duration) => {
      metrics.record('mcp_tool_duration_ms', duration, { toolName });
    },
    onToolError: async (toolName, error) => {
      logger.error('MCP tool failed', { toolName, errorName: error.name });
    },
  })
  .build();
```

`onRequest`, `onResponse`, and `onError` exist in the options type but are not dispatched by the current adapter. Custom tools do not pass through these router-tool hooks. Avoid logging raw arguments, which may contain credentials or personal data.
