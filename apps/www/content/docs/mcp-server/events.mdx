## Supported tool events

The adapter invokes three event callbacks around automatically mapped router tools: <code>onToolCall</code>, <code>onToolSuccess</code>, and <code>onToolError</code>. It does not currently invoke request-wide, response-wide, or general adapter error hooks. Custom tools do not pass through these callbacks.

<Callout type="info" title="Scope">
  These hooks run only for actions mapped from the Igniter router. Put authorization and request-wide controls in your route middleware or application layer.
</Callout>

## Configure the hooks

The function API and builder accept the same <code>McpEventsOptions</code> object:

~~~typescript
import { IgniterMcpServer } from '@igniter-js/adapter-mcp-server';
import { AppRouter } from '@/igniter.router';

const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .withEvents({
    onToolCall: async (toolName, args, context) => {
      console.info('Starting MCP tool', {
        toolName,
        client: context.client,
        timestamp: context.timestamp,
      });
    },
    onToolSuccess: async (toolName, result, duration, context) => {
      console.info('MCP tool completed', { toolName, duration });
    },
    onToolError: async (toolName, error, context) => {
      console.error('MCP tool failed', { toolName, message: error.message });
    },
  })
  .build();

export const GET = handler;
export const POST = handler;
~~~

For the function API, pass the same callbacks under <code>events</code>:

~~~typescript
const { server } = createMcpAdapter({
  router: AppRouter,
  events: {
    onToolCall: async (toolName, args, context) => {
      await audit.record({ toolName, args, timestamp: context.timestamp });
    },
    onToolSuccess: async (toolName, result, duration) => {
      await metrics.record('mcp.tool.duration', duration, { toolName });
    },
    onToolError: async (toolName, error) => {
      await errorTracker.capture(error, { toolName });
    },
  },
});

export const GET = server;
export const POST = server;
~~~

## Callback order

For a router-backed tool call, the adapter calls <code>onToolCall</code> before invoking the Igniter action. If the action completes, it calls <code>onToolSuccess</code> with the result and elapsed milliseconds. If the hook or action throws, it calls <code>onToolError</code>, then returns the configured error response or its default error result.

Throwing from <code>onToolCall</code> prevents the action from running. This can be used as a tool-level guard, but use route middleware for controls that must apply to every transport request.

## Context and safe logging

Each callback receives an <code>McpContext</code> containing the router context, the request, a timestamp, client user-agent information, and the adapter's tool list. The <code>client</code> value is the request's user-agent header or <code>unknown</code>; it is not an authenticated user or a stable client identity.

Treat tool arguments and router context as potentially sensitive. Redact credentials and personal data before logging. Do not treat the incoming request body as parsed tool arguments; use the <code>args</code> parameter supplied to <code>onToolCall</code>.

## Unsupported event properties

The public options type currently also declares <code>onRequest</code>, <code>onResponse</code>, and <code>onError</code>, but the adapter does not call them. Use your framework's middleware or route wrapper for request/response instrumentation until those hooks are implemented.
