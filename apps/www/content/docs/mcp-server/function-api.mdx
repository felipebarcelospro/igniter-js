## Overview

`createMcpAdapter` creates the MCP handler from a router and one configuration object. Use it when you prefer object-based configuration over the [builder API](/docs/mcp-server/builder-pattern).

## Basic setup

```typescript
import { createMcpAdapter } from '@igniter-js/adapter-mcp-server';
import { AppRouter } from '@/igniter.router';

const { server } = createMcpAdapter({
  router: AppRouter,
  serverInfo: { name: 'Acme API', version: '1.0.0' },
  instructions: 'Use the available tools to manage users and products.',
});

export const GET = server;
export const POST = server;
```

The returned object includes `server` and `auth` handlers. Token enforcement is enabled only when OAuth is configured with `verifyToken`.

## Configure tools

Router actions are mapped to tools by default. Use the filter to allow only selected controller/action pairs. The transform must return a tool configuration; it cannot remove a tool by returning `null`.

```typescript
const { server } = createMcpAdapter({
  router: AppRouter,
  tools: {
    autoMap: true,
    naming: (controller, action) => `${controller}_${action}`,
    filter: (controller, action) => controller === 'users' && action !== 'delete',
    transform: (controller, action, actionConfig) => ({
      name: `${controller}_${action}`,
      description: actionConfig.description ?? `Run ${controller}.${action}`,
      // Leave schema undefined to preserve generated body, query, and path inputs.
    }),
  },
});
```

`actionConfig` exposes the action's `description`, `method`, and `path`. It does not provide `summary` or `tags`. Custom tools can be added through `tools.custom`; see [Custom Tools](/docs/mcp-server/custom-tools).

## Prompts and resources

You can add custom prompts and resources using `prompts.custom` and `resources.custom`. At present, configure at most one prompt because multiple configured prompts are registered repeatedly by the adapter. Resource definitions accept `name`, `uri`, and a `handler`; the callback receives `(uri, extra)` and should return an MCP `ReadResourceResult`. Resource description and MIME metadata are not passed through by this adapter. See [Prompts and Resources](/docs/mcp-server/prompts-resources) for exact signatures and limitations.

## OAuth

OAuth enforcement is enabled when `verifyToken` is configured. Return an MCP `AuthInfo` object for valid tokens, or `undefined` to reject them:

```typescript
const { server, auth } = createMcpAdapter({
  router: AppRouter,
  oauth: {
    issuer: process.env.OAUTH_ISSUER!,
    scopes: ['mcp:read'],
    verifyToken: async ({ bearerToken }) => {
      const claims = await verifyJWT(bearerToken);
      if (!claims) return undefined;

      return {
        token: bearerToken,
        clientId: claims.clientId,
        scopes: claims.scopes,
        extra: { subject: claims.sub },
      };
    },
  },
});

export const GET = server;
export const POST = server;
export const OPTIONS = auth.cors;
```

The adapter does not automatically add `AuthInfo` to the Igniter router context. See [OAuth](/docs/mcp-server/oauth) for metadata routes and deployment details.

## Events and responses

The adapter currently invokes `onToolCall`, `onToolSuccess`, and `onToolError` for router-mapped tool calls. Other event properties in the options type are not dispatched. A response `transform` can format successful router action results; `onError` can customize an error result. See [Events](/docs/mcp-server/events).

## Adapter options

```typescript
const { server } = createMcpAdapter({
  router: AppRouter,
  adapter: {
    basePath: '/api/mcp',
    maxDuration: 60, // seconds
    verboseLogs: true,
    redisUrl: process.env.REDIS_URL,
  },
});
```

`redisUrl` is forwarded to the MCP handler. The nested `adapter.redis` field in the public type is currently not forwarded by the adapter. `maxDuration` is measured in seconds.
