title: Best Practices
description: Design safe, understandable, and maintainable MCP tools with the Igniter.js adapter.
---

## Expose only intended actions

Router actions are mapped to tools by default. Review the exposed set before connecting an MCP client, and exclude administrative or destructive actions that the client should not call:

```typescript
const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .withToolFilter(['users.delete', 'billing.refund'], 'exclude')
  .build();
```

Tool filtering is an exposure control; authorization for the underlying operation still belongs in the action and application. See [OAuth](/docs/mcp-server/oauth) when clients must authenticate to the MCP endpoint.

## Validate and describe inputs

Use schemas on router actions and custom tools so clients receive useful input shapes. Keep descriptions specific about units, allowed values, and side effects:

```typescript
import { IgniterMcpServer } from '@igniter-js/adapter-mcp-server';
import { z } from 'zod';

const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .addTool({
    name: 'calculateTax',
    description: 'Calculate tax for a purchase amount in USD.',
    args: {
      amount: z.number().positive().describe('Purchase amount in USD'),
      rate: z.number().min(0).max(1).describe('Tax rate as a decimal'),
    },
    handler: async ({ amount, rate }) => ({
      content: [{ type: 'text', text: (amount * rate).toFixed(2) }],
    }),
  })
  .build();
```

## Keep tool calls observable without leaking data

The adapter invokes `onToolCall`, `onToolSuccess`, and `onToolError` for router-mapped tool execution. These hooks do not cover HTTP lifecycle events or custom tools. Tool arguments can contain secrets, so avoid logging them wholesale:

```typescript
.withEvents({
  onToolCall: async (toolName) => {
    logger.info('MCP tool started', { toolName });
  },
  onToolSuccess: async (toolName, result, duration) => {
    metrics.record('mcp_tool_duration_ms', duration, { toolName });
  },
  onToolError: async (toolName, error) => {
    logger.error('MCP tool failed', {
      toolName,
      errorName: error.name,
    });
  },
})
```

Do not assume an event hook is a request rate limiter or authorization boundary. Apply those controls in your hosting layer and application actions.

## Return clear, bounded results

Return focused results that help the client decide what to do next. Avoid unnecessary records and redact private fields before serializing data:

```typescript
return {
  content: [{
    type: 'text',
    text: JSON.stringify({ id: user.id, name: user.name }),
  }],
};
```

## Handle errors safely

Use response error handling to return a useful message without exposing stack traces, credentials, or internal infrastructure details. Keep detailed diagnostics in protected server logs.

## Test important paths

Test custom tool handlers with valid and invalid inputs, and verify that the deployed MCP handler exposes only the intended tools. For OAuth-enabled servers, test both valid and invalid bearer tokens. Tool event hooks are not invoked for custom tools in the current implementation.
