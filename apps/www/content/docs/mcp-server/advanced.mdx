## Control which router actions become tools

By default, router actions are mapped to MCP tools. The builder's `withToolFilter` accepts router paths such as `users.list` and an `include` or `exclude` mode:

```typescript
const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .withToolFilter(['users.delete', 'admin.list'], 'exclude')
  .build();
```

The filter uses controller/action paths. For the function API, use `tools.filter`:

```typescript
const { server } = createMcpAdapter({
  router: AppRouter,
  tools: {
    filter: (controller, action) => controller === 'users' && action !== 'delete',
  },
});
```

Do not use `actionConfig.tags` or `actionConfig.summary`: those fields are not part of the action config passed to adapter callbacks. The available description, method, and path can be used to customize a tool.

## Transform generated tool definitions

Transforms return a complete tool configuration and cannot exclude a tool by returning `null`. Omit `schema` to retain the generated inputs derived from the action's body, query, and path parameters.

```typescript
const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .withToolTransform((controller, action, actionConfig) => ({
    name: `${controller}_${action}`,
    description: actionConfig.description ?? `Run ${controller}.${action}`,
  }))
  .build();
```

Tool names are normally generated as `<controller>_<action>` and sanitized for MCP. See [Getting Started](/docs/mcp-server/getting-started) for examples of generated names.

## Adapter runtime options

The function API accepts these adapter settings:

```typescript
const { server } = createMcpAdapter({
  router: AppRouter,
  adapter: {
    basePath: '/api/mcp',
    maxDuration: 60, // seconds
    verboseLogs: true,
    redisUrl: process.env.REDIS_URL,
  },
});
```

`maxDuration` is in seconds. `redisUrl` is forwarded to the MCP handler; the typed `adapter.redis` option is not currently forwarded. `verboseLogs` enables the adapter's verbose setting.

## Responses and errors

Use response callbacks to customize results from router-backed tools:

```typescript
const { server } = createMcpAdapter({
  router: AppRouter,
  response: {
    transform: async (result, toolName) => ({
      content: [{ type: 'text', text: `${toolName}: ${JSON.stringify(result)}` }],
    }),
    onError: async (error, toolName) => ({
      content: [{ type: 'text', text: `Unable to run ${toolName}: ${error.message}` }],
      isError: true,
    }),
  },
});
```

Avoid returning internal details or secrets in messages sent to clients. Log only sanitized values.

## Logger

The builder accepts a logger with `log`, `error`, `warn`, and `debug` methods. In the current adapter implementation, initialization calls `debug`; the other methods are not currently used.

## Capabilities

The builder's `withCapabilities` passes MCP server capability declarations through to the SDK. Declare only capabilities the server actually implements. For example, registering static prompts or resources does not by itself mean the server supports resource subscriptions or dynamic list changes.

```typescript
import type { ServerCapabilities } from '@modelcontextprotocol/sdk/types.js';

const capabilities: ServerCapabilities = { tools: {} };

const { handler } = IgniterMcpServer
  .create()
  .router(AppRouter)
  .withCapabilities(capabilities)
  .build();
```
