## Overview

`store.kv` provides the fundamental key-value interface for `@igniter-js/store`. All values are automatically serialized to JSON by the adapter, so you can store any JSON-serializable data without manual conversion.

<Callout type="info">
  The key format is auto-prefixed by the store: `igniter:store:{service}[:scope...]:kv:{your-key}`. You only provide the logical key — scoping is handled transparently.
</Callout>

## Basic Operations

### `get<T>(key)` — Retrieve a value

```typescript
const user = await store.kv.get<{ name: string; email: string }>("user:123");

if (user) {
  console.log(user.name); // Fully typed
}
```

Returns `null` if the key doesn't exist.

### `set(key, value, options?)` — Store a value

```typescript
// Store indefinitely
await store.kv.set("user:123", { name: "Avery", email: "avery@example.com" });

// Store with TTL (time-to-live in seconds)
await store.kv.set("session:abc", sessionData, { ttl: 3600 }); // 1 hour
```

### `remove(key)` — Delete a key

```typescript
await store.kv.remove("user:123");

// Invalidate cache after update
await db.user.update({ where: { id: "123" }, data: newData });
await store.kv.remove("user:123");
```

### `exists(key)` — Check existence

```typescript
const exists = await store.kv.exists("user:123");

if (!exists) {
  const user = await fetchFromDatabase("123");
  await store.kv.set("user:123", user, { ttl: 3600 });
}
```

### `expire(key, ttlSeconds)` — Set/update TTL

```typescript
// Set TTL on existing key
await store.kv.set("config:app", config);
await store.kv.expire("config:app", 86400); // 24 hours

// Refresh TTL on access
const data = await store.kv.get("cache:key");
if (data) {
  await store.kv.expire("cache:key", 3600); // Extend
}
```

### `touch(key, ttlSeconds)` — Set TTL on existing key

```typescript
// `touch` is like `expire` but semantically signals "this key was accessed"
await store.kv.touch("user:123", 3600);
```

## Cache Patterns

### Cache-Aside (Read-Through)

The most common pattern: check cache first, fall back to source.

```typescript
async function getUser(id: string) {
  const cacheKey = `user:${id}`;

  // 1. Check cache
  const cached = await store.kv.get<User>(cacheKey);
  if (cached) return cached;

  // 2. Fetch from database
  const user = await db.user.findUnique({ where: { id } });
  if (!user) return null;

  // 3. Populate cache
  await store.kv.set(cacheKey, user, { ttl: 3600 });

  return user;
}
```

### Write-Through

Update cache and source simultaneously.

```typescript
async function updateUser(id: string, data: Partial<User>) {
  const user = await db.user.update({ where: { id }, data });
  await store.kv.set(`user:${id}`, user, { ttl: 3600 });
  return user;
}
```

### Cache Invalidation

```typescript
async function invalidateUserCache(userId: string) {
  await store.kv.remove(`user:${userId}`);
  await store.kv.remove(`user:${userId}:posts`);
  await store.kv.remove("users:list");
}
```

### Conditional Caching

```typescript
async function getExpensiveData(params: QueryParams) {
  const cacheKey = `data:${JSON.stringify(params)}`;
  const cached = await store.kv.get<Data>(cacheKey);
  if (cached) return cached;

  const data = await expensiveOperation(params);

  // Only cache successful responses
  if (data.status === "success") {
    await store.kv.set(cacheKey, data, { ttl: 300 });
  }

  return data;
}
```

## TTL Management

### Choosing TTL Values

| Data type | Example | Recommended TTL |
|-----------|---------|----------------|
| Real-time data | Stock prices | 15–60s |
| User sessions | Auth tokens | 900–3600s |
| API responses | External API cache | 300–600s |
| Configuration | App settings | 3600–86400s |
| Static content | Page content | 86400s+ |

### Refresh-on-Access

```typescript
async function getWithRefresh<T>(key: string, ttl: number): Promise<T | null> {
  const value = await store.kv.get<T>(key);
  if (value) {
    await store.kv.touch(key, ttl); // Extend lifetime
  }
  return value;
}
```

## Key Naming Conventions

Use colons (`:`) for hierarchical names:

```typescript
// Entity patterns
`user:${userId}`                    // Single entity
`users:list`                        // Collection
`users:list:page:${pageNumber}`    // Paginated

// Feature patterns
`session:${sessionId}`              // User session
`rate:limit:${userId}`              // Rate limiting
`api:response:${endpoint}`          // API cache

// Multi-tenant patterns
`tenant:${tenantId}:user:${userId}` // Tenant-scoped
`env:${env}:config:${key}`          // Environment-scoped
```

<Callout type="info" title="Best Practice">
  Use **scopes** (`addScope()` / `.scope()`) for tenant isolation instead of manual key prefixes. Scopes automatically handle key construction and prevent collisions.
</Callout>

## Error Handling

```typescript
async function safeGet<T>(key: string): Promise<T | null> {
  try {
    return await store.kv.get<T>(key);
  } catch (error) {
    if (error instanceof IgniterStoreError) {
      console.error(`Store error [${error.code}]:`, error.message);
    }
    return null; // Graceful degradation
  }
}
```

## Real-World Examples

### API Response Caching

```typescript
async function fetchWithCache(endpoint: string, params: Record<string, string>) {
  const cacheKey = `api:${endpoint}:${JSON.stringify(params)}`;

  const cached = await store.kv.get<ApiResponse>(cacheKey);
  if (cached) return { ...cached, source: "cache" };

  const data = await fetchFromApi(endpoint, params);
  await store.kv.set(cacheKey, data, { ttl: 600 });

  return { ...data, source: "api" };
}
```

### Session Management

```typescript
async function createSession(userId: string): Promise<string> {
  const sessionId = crypto.randomUUID();
  await store.kv.set(
    `session:${sessionId}`,
    { userId, createdAt: new Date().toISOString() },
    { ttl: 86400 } // 24 hours
  );
  return sessionId;
}

async function getSession(sessionId: string) {
  const session = await store.kv.get<SessionData>(`session:${sessionId}`);
  if (session) {
    await store.kv.touch(`session:${sessionId}`, 86400); // Refresh
  }
  return session;
}

async function deleteSession(sessionId: string) {
  await store.kv.remove(`session:${sessionId}`);
}
```

### Feature Flags

```typescript
async function isFeatureEnabled(feature: string, userId?: string): Promise<boolean> {
  // Check global flag
  const globalFlag = await store.kv.get<boolean>(`flag:global:${feature}`);
  if (globalFlag !== null) return globalFlag;

  // Check user-specific override
  if (userId) {
    const userFlag = await store.kv.get<boolean>(`flag:user:${userId}:${feature}`);
    if (userFlag !== null) return userFlag;
  }

  return false; // Default off
}
```

## Performance Tips

### Prefer Parallel Gets

```typescript
// ✅ Good — parallel
const [user1, user2, user3] = await Promise.all([
  store.kv.get("user:1"),
  store.kv.get("user:2"),
  store.kv.get("user:3"),
]);

// ❌ Bad — sequential (slower)
const user1 = await store.kv.get("user:1");
const user2 = await store.kv.get("user:2");
const user3 = await store.kv.get("user:3");
```

### Use `exists` instead of `get` for presence checks

```typescript
// ✅ Good — no value deserialization
if (await store.kv.exists("key")) { /* ... */ }

// ❌ Bad — deserializes value unnecessarily
const val = await store.kv.get("key");
if (val !== null) { /* ... */ }
```
