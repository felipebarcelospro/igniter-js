## Overview

This guide covers advanced `@igniter-js/store` features for production applications: multi-tenant isolation with scopes, observability via telemetry, custom serializers, and building custom adapters.

## Scopes — Multi-Tenant Isolation

Scopes automatically prefix all keys with tenant identifiers, providing data isolation without manual key management.

### Defining Scopes

```typescript
import { IgniterStore } from "@igniter-js/store";

const store = IgniterStore.create()
  .withAdapter(adapter)
  .withService("api")
  .addScope("organization", {
    required: true,
    description: "Organization tenant",
  })
  .addScope("workspace") // Optional, no description
  .build();
```

### Using Scoped Stores

```typescript
// Type-safe — only "organization" | "workspace" allowed
const orgStore = store.scope("organization", "org_123");

// All keys are automatically prefixed:
// igniter:store:api:organization:org_123:kv:{your-key}
await orgStore.kv.set("settings", { theme: "dark" });

// The scoped store has the same API as the root store
await orgStore.counter.increment("api-calls");
await orgStore.events.publish("user:created", { /* ... */ });
```

### Chained Scopes

```typescript
const scoped = store
  .scope("organization", "org_123")
  .scope("workspace", "ws_456");

// Key: igniter:store:api:organization:org_123:workspace:ws_456:kv:config
await scoped.kv.set("config", { feature: true });

// Works with all operations
const streamConsumer = scoped.streams.group("workers", "w-1");
await streamConsumer.ensure("events");
```

### Scope Validation

```typescript
const store = IgniterStore.create()
  .withAdapter(adapter)
  .withService("api")
  .addScope("organization") // Only "organization" is valid
  .build();

store.scope("organization", "org_1"); // ✅ OK
// store.scope("workspace", "ws_1");  // ❌ TypeScript error + runtime: STORE_INVALID_SCOPE_KEY
```

<Callout type="success" title="Best Practice">
  Define scopes with `addScope()` for type safety. Without definitions, any scope key is accepted at the TypeScript level, but you lose compile-time validation.
</Callout>

### Multi-Tenant Example: SaaS Pricing Cache

```typescript
const store = IgniterStore.create()
  .withAdapter(adapter)
  .withService("billing")
  .addScope("tenant_id", { required: true })
  .build();

// Per-request, scope to the current tenant
async function getProductPricing(tenantId: string, productId: string) {
  const tenantStore = store.scope("tenant_id", tenantId);
  const key = `product:${productId}:pricing`;

  let pricing = await tenantStore.kv.get(key);
  if (!pricing) {
    pricing = await db.pricing.findUnique({
      where: { tenantId, productId },
    });
    await tenantStore.kv.set(key, pricing, { ttl: 3600 });
  }

  return pricing;
}
```

## Telemetry Integration

`@igniter-js/store` emits typed telemetry events for every operation when you configure telemetry.

### Setup

```typescript
import { IgniterTelemetry } from "@igniter-js/telemetry";
import { IgniterStoreTelemetryEvents } from "@igniter-js/store/telemetry";
import { IgniterStore } from "@igniter-js/store";

// 1. Create telemetry manager with store events
const telemetry = IgniterTelemetry.create()
  .withService("api")
  .addEvents(IgniterStoreTelemetryEvents)
  .withRedaction({
    denylistKeys: ["value", "message", "payload", "data"],
    hashKeys: ["ctx.store.key"],
  })
  .build();

// 2. Wire into store
const store = IgniterStore.create()
  .withAdapter(adapter)
  .withService("api")
  .withTelemetry(telemetry)
  .build();
```

### Telemetry Events Emitted

| Event | Trigger |
|-------|---------|
| `igniter.store.kv.get.started` | `store.kv.get()` called |
| `igniter.store.kv.get.success` | `store.kv.get()` succeeds |
| `igniter.store.kv.get.error` | `store.kv.get()` fails |
| `igniter.store.kv.set.*` | `store.kv.set()` lifecycle |
| `igniter.store.counter.increment.*` | `store.counter.increment()` lifecycle |
| `igniter.store.claim.acquire.*` | `store.claim.once()` lifecycle |
| `igniter.store.batch.get.*` | `store.batch.get()` lifecycle |
| `igniter.store.events.publish.*` | `store.events.publish()` lifecycle |
| `igniter.store.stream.append.*` | `store.streams.append()` lifecycle |
| `igniter.store.dev.scan.*` | `store.dev.scan()` lifecycle |

### Event Attributes

Every event includes:

```typescript
{
  "ctx.store.service": "api",           // Service name
  "ctx.store.namespace": "kv",          // Operation namespace
  "ctx.store.scope_key": "organization", // Scope type (if scoped)
  "ctx.store.scope_depth": 2,           // Scope chain depth
}
```

<Callout type="warn" title="Redaction is critical">
  Telemetry events may contain key names. Always configure `withRedaction()` to hash or deny-list sensitive fields like `key`, `value`, and `message`. The recommended configuration:
  ```typescript
  .withRedaction({
    denylistKeys: ["value", "message", "payload", "data"],
    hashKeys: ["ctx.store.key"],
  })
  ```
</Callout>

## Custom Serializer

By default, the Redis adapter uses `JSON.stringify`/`JSON.parse`. Provide a custom serializer for MessagePack or other formats:

```typescript
import { encode, decode } from "@msgpack/msgpack";

const store = IgniterStore.create()
  .withAdapter(adapter)
  .withService("api")
  .withSerializer({
    encode: (value: unknown): string =>
      Buffer.from(encode(value)).toString("base64"),
    decode: (value: string): unknown =>
      decode(Buffer.from(value, "base64")),
  })
  .build();
```

### Serializer Interface

```typescript
interface IgniterStoreSerializer {
  encode(value: unknown): string;
  decode(value: string): unknown;
}
```

## Adapters

### Redis Adapter (Production)

```typescript
import { IgniterStoreRedisAdapter } from "@igniter-js/store/adapters";
import Redis from "ioredis";

const redis = new Redis(process.env.REDIS_URL);
const adapter = IgniterStoreRedisAdapter.create({ redis });
```

The Redis adapter internally creates a **duplicate client** for Pub/Sub subscriptions (Redis requirement). Your main client stays dedicated to commands.

### Memory Adapter (Testing & Desktop)

```typescript
import { IgniterStoreMemoryAdapter } from "@igniter-js/store/adapters";

const adapter = IgniterStoreMemoryAdapter.create();

// Supports: kv, counter, claim, batch, pub/sub, streams, scan
// Ideal for: unit tests, Electron apps, Tauri apps, CI pipelines
```

### Building a Custom Adapter

Implement the `IgniterStoreAdapter` interface:

```typescript
import type { IgniterStoreAdapter, IgniterStoreBatchEntry } from "@igniter-js/store";

class CustomAdapter implements IgniterStoreAdapter<MyClient> {
  client: MyClient;

  constructor(client: MyClient) {
    this.client = client;
  }

  // Required: Key-Value
  async get<T>(key: string): Promise<T | null> { /* ... */ }
  async set(key: string, value: unknown, options?: { ttl?: number }): Promise<void> { /* ... */ }
  async delete(key: string): Promise<void> { /* ... */ }
  async has(key: string): Promise<boolean> { /* ... */ }

  // Required: Atomic
  async increment(key: string, delta?: number): Promise<number> { /* ... */ }
  async expire(key: string, ttl: number): Promise<void> { /* ... */ }
  async setNX(key: string, value: unknown, options?: { ttl?: number }): Promise<boolean> { /* ... */ }

  // Required: Batch
  async mget<T>(keys: string[]): Promise<(T | null)[]> { /* ... */ }
  async mset(entries: IgniterStoreBatchEntry[]): Promise<void> { /* ... */ }

  // Required: Pub/Sub
  async publish(channel: string, message: unknown): Promise<void> { /* ... */ }
  async subscribe(channel: string, callback: (msg: unknown) => void | Promise<void>): Promise<void> { /* ... */ }
  async unsubscribe(channel: string, callback?: (msg: unknown) => void | Promise<void>): Promise<void> { /* ... */ }

  // Required: Scan
  async scan(pattern: string, options?: { cursor?: string; count?: number }): Promise<{ keys: string[]; cursor: string }> { /* ... */ }

  // Required: Streams
  async xadd(stream: string, message: unknown, options?: { maxLen?: number; approximate?: boolean }): Promise<string> { /* ... */ }
  async xgroupCreate(stream: string, group: string, startId?: string): Promise<void> { /* ... */ }
  async xreadgroup<T>(stream: string, group: string, consumer: string, options?: { count?: number; blockMs?: number }): Promise<Array<{ id: string; message: T }>> { /* ... */ }
  async xrange<T>(stream: string, options?: { startId?: string; endId?: string; count?: number }): Promise<Array<{ id: string; message: T }>> { /* ... */ }
  async xrevrange<T>(stream: string, options?: { startId?: string; endId?: string; count?: number }): Promise<Array<{ id: string; message: T }>> { /* ... */ }
  async xack(stream: string, group: string, ids: string[]): Promise<void> { /* ... */ }
}
```

## Logger Integration

```typescript
const store = IgniterStore.create()
  .withAdapter(adapter)
  .withService("api")
  .withLogger({
    info: (msg, meta) => console.log(`[INFO] ${msg}`, meta),
    warn: (msg, meta) => console.warn(`[WARN] ${msg}`, meta),
    error: (msg, meta) => console.error(`[ERROR] ${msg}`, meta),
    debug: (msg, meta) => console.debug(`[DEBUG] ${msg}`, meta),
  })
  .build();

// Access logger from the store instance
store.logger?.info("Store initialized");
```

## Framework Integration

### Next.js (App Router)

```typescript
// lib/store.ts
import { IgniterStore } from "@igniter-js/store";
import { IgniterStoreRedisAdapter } from "@igniter-js/store/adapters";
import Redis from "ioredis";

const redis = new Redis(process.env.REDIS_URL!);

export const store = IgniterStore.create()
  .withAdapter(IgniterStoreRedisAdapter.create({ redis }))
  .withService("next-app")
  .build();

// app/api/users/[id]/route.ts
import { NextResponse } from "next/server";
import { store } from "@/lib/store";

export async function GET(_: Request, { params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  const user = await store.kv.get(`user:${id}`);

  if (!user) {
    return NextResponse.json({ error: "Not found" }, { status: 404 });
  }

  return NextResponse.json({ user });
}
```

### Express

```typescript
import express from "express";
import { store } from "./store";

const app = express();

app.get("/users/:id", async (req, res) => {
  const user = await store.kv.get(`user:${req.params.id}`);
  res.json({ user });
});

app.listen(3000);
```

### Fastify

```typescript
import Fastify from "fastify";
import { store } from "./store";

const app = Fastify();

app.get("/users/:id", async (req) => {
  const user = await store.kv.get(`user:${(req.params as any).id}`);
  return { user };
});

await app.listen({ port: 3000 });
```
